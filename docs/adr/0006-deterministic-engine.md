# ADR-0006: Deterministic, pure draw engine

- Status: Accepted (2026-09-11)

## Context

When a contingent disputes a draw, the committee must be able to show that the same input,
rules, engine version and seed produce exactly the same result — and that nothing else
influenced it. Hidden nondeterminism (clock, `Math.random`, locale-dependent sorting, floating-point
drift, random UUIDs, insertion order) would make that impossible.

## Decision

The engine is a pure function `(input, rules, seed) → output`:

| Source of nondeterminism | Rule                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Randomness               | Only `Prng` (xoshiro128**) from `@bagantkd/shared`. State = SHA-256(`prefix ␀ seed ␀ label`)[0..16]; one stream per label (e.g. per category), so re-drawing one category never shifts another. |
| Seeds                    | Unsigned 64-bit integers written in decimal, stored on every `draw_run`.                                                                                                                        |
| Clock                    | Never read inside pure packages. The worker measures wall time around the engine.                                                                                                               |
| Numbers                  | Integer units: millimetres, grams, belt ranks. Costs are fixed-point integers (`FP_SCALE = 10_000`), weights per mille; overflow throws instead of wrapping.                                    |
| Ordering                 | Explicit total-order comparators ending in a unique id; `compareStrings` orders by UTF-16 code units; never `localeCompare`.                                                                    |
| Identifiers              | `deterministicUuid(namespace, name)` (UUIDv8 from SHA-256) for pool/match identities.                                                                                                           |
| Serialization            | Canonical JSON (sorted keys, strict types) → SHA-256 fingerprint for input, rules, output and quality report.                                                                                   |
| Replay check             | Candidate runs execute the engine twice; a run is `SAFE` only if both output fingerprints match (DB check `draw_run_candidate_dual_run_ck`).                                                    |

## Consequences

- Any run can be reproduced from its stored snapshot and seed, bit-for-bit.
- Engine code is testable without mocks, and runs identically in Node and the browser.
- Floating-point is not banned by the compiler; it is kept out by review, lint on known sources,
  and fixed-point helpers that assert safe integers.

## Alternatives rejected

- `Math.random` with a recorded seed — not seedable in JavaScript.
- Floating-point costs — results could differ across engines and optimizations.

## Enforced by

- ESLint on pure packages forbids `Math.random`, `Date.now`, `new Date`, `performance`,
  `crypto.randomUUID`, `localeCompare` (verified by a probe file in Phase 1).
- Known-answer vectors for the PRNG, canonical fingerprint and UUID, generated by an
  **independent Python implementation** (`packages/shared/src/*.test.ts`).
- Property tests: replay identity for any 64-bit seed; permutation and bounds properties.
- INV-05 replay test in `packages/draw-engine/src/run.test.ts` and in the simulator.
